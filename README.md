# Demonia (MSX, 1986) — a commented disassembly

*(También disponible [en castellano](README.es.md).)*

A complete, byte-for-byte reproducible disassembly of the Demonia cassette for
the MSX1. The listing is generated from a real control-flow trace, not from a
linear disassembly, and `make verify` checks that reassembling it gives the
original `.cas` back, with the same sha256.

**The web version, with the pictures:** [antxiko.github.io/Demonia-disassembly](https://antxiko.github.io/Demonia-disassembly/)

## The tape is not here

This repository holds only the documentation work. To rebuild everything you
need your own copy of the tape, named `demonia.cas` in the root, with this
sha256:

    69031ee25099df0703332ca74a64b52e6dd9909e4cfded4c3699be153adc5fc9

## What is odd about this game

It does not fit in the RAM an MSX booted into BASIC can see. What it does is
look for a slot with 64 KB and hide 26 KB **underneath the BASIC ROM**, in
pages 0 and 1. The seven blocks the tape carries behind the loader are not run
where they land: each one has a little routine glued to it that switches the
slot, does an `LDIR` and switches it back.

That is why there are thirteen listings here and not seven, and why verify
takes two steps: first each listing, then gluing the chunks back together in
the tape's own order.

And there is more, told in [docs/FINDINGS.md](docs/FINDINGS.md): inside the
game block travels a whole **machine code monitor** by Loriciels, from 1984, by
the same author — with its entry point still wired up and its commands already
useless.

## Some of what turned up

- A 1984 Loriciels machine code monitor, **4,377 bytes**, stowed away inside a
  1986 game by the same author.
- Its back door is still live: `CTRL+STOP` sets INTFLG to 3 and `0x9C72` calls
  the monitor.
- But its command table at `0xD5C6` was **buried under the game's own screen
  records**, so it boots, paints the registers and obeys nothing. That accounts
  for 2,094 bytes of unreachable code.
- In its single-step buffer, `ld hl,(0x8078)`: the last instruction that monitor
  ever stepped before someone saved the tape.
- Three files on the tape, **all called `DEMON`**, told apart by a `:RUN`.

## Usage

    make verify     # extract, trace, generate and check byte for byte
    make sanity     # trace coherence and the 100% budget
    make densidad   # comment density against the series bar
    make sobra      # the accounting for what the game never uses
    make test       # the tests
    make imagenes   # redraws the PNGs from the tape
    make web        # regenerates the site

You need `pasmo`, `z80dasm` and `python3`.

## The pictures are not screenshots

Everything in `docs/imagenes/` is **drawn from the tape's own bytes**:
`tools/mapas.py` replays the game's decompressor over the compressed maps and
then develops each tile the way the VDP would, using the patterns at `0x6000`
and the colours at `0x6800`. The wordmark at the top of the site is the first
eight rows of the game's own title screen, cropped by the same tool.

If a range were mislabelled, it would come out as noise.
